# Pulse Weaver 2.0.0 unstable 5

Build my show now starts with the kind of stream you want to make, then follows **Activity → Inputs → Views → Screens → Alerts → Review**. You can start without learning the internal Stage/Look/Feed model or supplying external artwork links.

- Assign your camera, content and optional detail/guest input once. Generated screens reuse those sources. Cameras are optional for games and creative work.
- Choose genuinely different views: content, presenter, detail, combined, two-camera or three-input compositions, as supported by your assigned inputs. Cosmetic duplicates no longer fill the default route. Content fits inside either canvas; camera/detail cropping is an explicit framing choice.
- Create Starting, Break and Ending with editable, built-in static artwork. Custom browser artwork can replace either format independently. The static Starting card is not a countdown.
- Add up to **three alert layers**, each grouping landscape and portrait links. Choose Main-only or all-screen placement. Disabled layers create no browsers.
- Review real input names, artwork fallbacks and alert assignments. Back and focused edits preserve your other answers. Saved layouts and specialist work remain available through detailed setup.

The flow draws on university HCI teaching, primary usability research, streamer studies and official production guidance. The [research and implementation notes](SETUP-WIZARD-TASK-FIRST-IMPLEMENTATION-2026-10-25.md) distinguish design evidence, complete-show coverage and remaining real-user validation. No independent novice study has been completed.

Validation includes a source-stable native build, **8,345 regression checks** across 15 completed-show scenarios plus the real wizard Finish path, and **204 readable Windows UI checks** at three window sizes. These cover source reuse, both canvas layouts, static card rendering, zero to three alert layers, preserved existing audio properties, cancellation and transactional rollback. Assertion counts are not counts of independent user tasks. Isolated native rendering and package/update evidence accompany the release validation.

Native movement, dual canvases, multistream, stingers, Lumia compatibility and existing audio/monitoring settings are retained. Newly created browser copies, including browser content, start with output audio off; select the intended audible copy and check real sound. The built-in cards use ordinary image sources, with no browser timers or network requirement. Game-load performance, live provider delivery and actual stinger/Lumia audio playback still require rehearsal with your show. No CPU/RAM reduction is claimed.

Use **Studio → Updates** with unstable builds enabled. This release supplies `PulseWeaver-Setup-2.0.0-unstable.5.exe` for an ordinary unstable installation and `PulseWeaver-2-Preview-Setup-2.0.0-unstable.5.exe` for the separate 2 Preview installation. Each retains its installation identity and recovery path. Stop outputs and close Pulse Weaver before setup. The Lumia 1.4.4 companion and existing wizard artwork remain compatible.
